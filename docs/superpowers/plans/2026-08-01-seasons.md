# 分季收藏（TV Seasons）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓使用者能為同一部影集記錄多筆收藏（各自對應不同季數區間），Grid View 把這些記錄視覺上疊成一張卡片，避免看起來像重複收藏；Calendar/Gallery 維持現況不分組。

**Architecture:** 後端新增 `seasons int[]` 欄位存使用者勾選的季數（沿用既有多次記錄 row-per-instance 架構，不新增資料表）；TMDB 季數 metadata 即時拉取不落地。前端新增一個純函式做「依 external_id 分組＋依 archived_date 排序」，只有 Grid View 消費它；詳情頁新增橫向 pills 切換器與季數資訊區塊；`AddToFolioModal` 新增季數勾選步驟。

**Tech Stack:** FastAPI + Pydantic + Supabase(Postgres) / Next.js 14 App Router + TypeScript + Tailwind

## Global Constraints

- 季數資料僅 `media_type === 'tv'` 有意義；`movie`/`book` 完全不受影響，`seasons` 恆為 `null`
- `seasons` 欄位 nullable，不回填舊資料（無需 backfill migration，跟 `archived_date` 那次不同）
- TMDB 季數 metadata（年份/集數/評分）即時拉取、不落地存 DB，不新增快取表（比照 `cast`/`genres` 既有模式）
- Grid View 的分組/排序一律依 `archived_date`（`dateUtils.getArchivedDate`），不是 `created_at`——與 Calendar/Gallery 既有邏輯、以及本次 session 稍早修復的 Monthly Recap bug 保持一致
- Calendar View 與 Gallery View **不需要任何程式碼變更**（維持攤平、不分組）
- 後端遵循 TDD（pytest，mock Supabase client，比照 `test_collection_repo.py`/`test_search_details.py` 既有慣例）
- **前端目前沒有單元測試框架**（無 Jest/Vitest；Playwright 落後且未進 CI，見 `CLAUDE.md`）。前端任務的驗證方式統一為：`npx tsc --noEmit` 型別檢查 + dev server 手動 QA，不新增測試框架（超出本次功能範圍）
- 卡片左上角既有「2ND VIEW」徽章文字**不變**（用戶已確認），新的疊層堆疊視覺與右上角記錄數徽章是額外新增的元素，不取代它

```sql
--
-- 背景：同一部影集（尤其 TV）可能分次收藏不同季數（如今年看完 S1-S3、
-- 明年看完 S4-S6）。每筆收藏維持獨立 row（沿用既有多次記錄機制），

-- 維持 null，前端會 fallback 顯示「第 N 次」而非季數範圍。

ALTER TABLE collections
  ADD COLUMN IF NOT EXISTS seasons integer[];

-- 驗證（執行後手動確認）
-- SELECT id, title, media_type, seasons FROM collections WHERE media_type = 'tv' ORDER BY created_at DESC LIMIT 5;
```

```typescript
import { Story } from '@/types';
import { getArchivedDate } from '@/lib/dateUtils';

export interface GroupedStory {
  /** 組內 archived_date 最新的一筆，Grid 卡面顯示這筆 */
  representative: Story;
  /** 組內所有記錄，依 archived_date 由新到舊排序 */
  instances: Story[];
}

/**
 * 依 external_id 分組，組內與組間都依 archived_date（非 created_at）由新到舊排序。
 * 用於 Grid View 的疊層卡片；Calendar/Gallery 不使用此函式，維持攤平顯示。
 */
export function groupStoriesByShow(stories: Story[]): GroupedStory[] {
  const groups = new Map<string, Story[]>();

  for (const story of stories) {
    const existing = groups.get(story.external_id);
    if (existing) {
      existing.push(story);
    } else {
      groups.set(story.external_id, [story]);
    }
  }

  const grouped: GroupedStory[] = [];
  groups.forEach((instances) => {
    const sorted = [...instances].sort((a, b) =>
      getArchivedDate(b).localeCompare(getArchivedDate(a))
    );
    grouped.push({ representative: sorted[0], instances: sorted });
  });

  return grouped.sort((a, b) =>
    getArchivedDate(b.representative).localeCompare(getArchivedDate(a.representative))
  );
}
```

```typescript
function formatSeasonLabel(seasons: number[] | null | undefined, fallbackViewingNumber: number): string {
  if (!seasons || seasons.length === 0) {
    return `第 ${fallbackViewingNumber} 次`;
  }
  const sorted = [...seasons].sort((a, b) => a - b);
  const ranges: string[] = [];
  let start = sorted[0];
  let prev = sorted[0];

  for (let i = 1; i <= sorted.length; i++) {
    const current = sorted[i];
    if (current !== prev + 1) {
      ranges.push(start === prev ? `S${start}` : `S${start}-S${prev}`);
      start = current;
    }
    prev = current;
  }

  return ranges.join(', ');
}
```
